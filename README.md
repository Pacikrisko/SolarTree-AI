# SolarTree AI

Уеб приложение за соларни дървета с профили, телеметрия и AI чат. **SyntheticO2** е физическият прототип с Raspberry Pi Pico 2 W. Той изпраща температура, влажност и суров сигнал от MQ-8. **Urban 2K** е симулиран модел.

## Стартиране на сървър

От корена на хранилището се изгражда **един Docker контейнер**. При изграждането Vite компилира React интерфейса. При стартиране FastAPI обслужва интерфейса и API на един порт. Нужни са Docker и достъпна PostgreSQL база.

1. Клонирай хранилището и влез в него.
2. Създай частен файл `.env.production` по таблицата по-долу. За нова инсталация можеш да генерираш `SECRET_KEY` с `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
3. Изпълни:

```sh
docker build -t solartree .
docker run -d --name solartree --restart unless-stopped --env-file .env.production -p 127.0.0.1:10000:10000 solartree
curl -fsS http://127.0.0.1:10000/api/health
```

Отвори `http://127.0.0.1:10000/` на сървъра. За публичен достъп насочи HTTPS reverse proxy към този адрес. При проблем виж `docker logs solartree`. Таблиците се създават при стартиране. Потребителите, разговорите, измерванията и регистрациите на устройства се съхраняват в PostgreSQL.

### Настройки

Във файла се пише по един ред `ИМЕ=стойност`. На управляван хостинг въведи същите променливи в настройките на услугата.

| Променлива | Стойност и предназначение |
| --- | --- |
| `APP_ENV` | `production` |
| `DEMO_MODE` | `false` за хостинг с реални акаунти |
| `DATABASE_URL` | Адрес на PostgreSQL, достъпен от контейнера. За Neon използвай предоставения connection string с TLS. |
| `SECRET_KEY` | Постоянна случайна тайна за сесиите. При преместване запази сегашната стойност. |
| `PUBLIC_SCANNER_URL` | Публичният HTTPS адрес на сайта за сдвояване с телефон. |
| `GOOGLE_CLIENT_ID` | За вход с Google. Добави публичния адрес в Authorized JavaScript origins на OAuth клиента. |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | За AI чата с Cloudflare Workers AI. Използвай сървърен токен с достъп до Workers AI. |
| `PORT` | По подразбиране `10000`. Управляваният хостинг може да зададе порта. |

### Render

Свържи съществуващото хранилище като Blueprint чрез [render.yaml](render.yaml). Той задава Docker, производствен режим и проверката `/api/health`. Въведи `DATABASE_URL`. При нова услуга Blueprint генерира `SECRET_KEY`. Добави настройките за желаните интеграции от таблицата. Интерфейсът и API се отварят от един и същ публичен адрес.

### Предаване на съществуващата инсталация

- Предай достъпа до базата и настройките на услугата по защитен канал. За да се запазят акаунтите, историята и сдвояването на Pico, използвай същата база или възстанови нейно резервно копие преди стартиране. Празната база изисква нова регистрация на устройствата.
- При смяна на домейна актуализирай `PUBLIC_SCANNER_URL`, разрешения адрес в Google и `HOST` във фърмуера на Pico. Провери съвместимостта на TLS сертификата на новия домейн с платката.
- Провери `/api/health` за `"ok":true` и `"simulation_enabled":false` (глобалният деморежим). След това провери входа, AI чата и часа на последното измерване за SyntheticO2. Самият Urban 2K остава симулатор.

## Устройства

[Настройване на Pico 2 W с CircuitPython](firmware/pico/README.md). При преместване със същата база запази индивидуалния ключ на вече сдвоеното устройство.

За **ново** физическо устройство администраторът може да изпълни в работещия контейнер:

```sh
docker exec -it solartree python provision_device.py --code IVAN-TREE-0001 --model ST-IVAN-P1 --kind private
```

Този пример е за първа регистрация на прототипа в празна база. Инструментът извежда отделни данни за сдвояване и телеметрия. За Urban 2K използвай код `URBAN-TREE-0001` и модел `ST-URBAN-2KW`. Примерните QR етикети в `docs/qr_examples` са за локалния деморежим.

## Локална разработка

В Windows стартирай `start_windows.bat` и отвори `http://127.0.0.1:5173`. Локалните настройки са в [backend/.env.example](backend/.env.example). GitHub Actions проверява backend тестовете, frontend компилацията и стартирането на контейнера.

## Администраторски панел

„Администрация“ показва регистрираните устройства, статуса на сдвояване и последната Pico проба. Създаването на Urban 2K издава сериен номер, QR и два индивидуални ключа. Изтегли ги преди затваряне на панела. Собственикът добавя симулатора чрез обичайната форма или QR.

След първото стартиране на актуализирания сървър оператор с достъп до PostgreSQL може да провери ID на избран съществуващ профил и да изпълни `UPDATE users SET is_admin = true WHERE id = <проверено ID>;`. За отнемане задава `false`. Обнови страницата след промяната. Правото за управление на устройства е отделно от собствеността върху дърветата.
